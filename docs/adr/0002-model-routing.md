# ADR-0002: 模型路由设计（智力/价格分层与策略评估）

> 状态：已采纳（2026-11-06）｜关联：F18（实现）、ADR-0001（Router 轻量模型思想来源）、F5 预算熔断、F16 预审、eval 引擎
> 一句话决策：**判断类调用与生成类调用是两种负载，按「调用类型 + 任务信号」分层选模型，用评测引擎做 A/B 验证路由策略。**

## 一、背景与现状

现状是 **agent 级静态路由**：每个 agent 绑定一个 `model` 字段，gateway 有模型注册表（`GET /models`）但不做选择。问题：
- 看门狗判进展、预审出风险标签、handoff 决策——这些**高频、短输出、延迟敏感**的判断类调用，和任务执行这种**长输出、质量敏感**的生成类调用，跑同一个模型，两边都不最优
- 本地 Ollama 里现成放着 lfm25:2.7B（小）与 qwen3.5 9B（中），未被分层使用

## 二、决策：三个粒度，按序演进

### 粒度 1：Agent 级（静态）——已有
角色决定默认档位。不动的部分：agent 的 `model` 字段保留为「该 agent 执行类调用的默认档」。

### 粒度 2：步骤级分流（半静态）——F18-a
同一 agent 内，**按调用类型**分流，不依赖任务特征，零预测风险：

| 调用类型 | 负载特征 | 档位 | agentfleet 实例 |
|---|---|---|---|
| 路由/判断 | 输出一个标签/短 JSON、高频、延迟敏感 | **S**（lfm25:2.7B） | handoff 决策、F14 看门狗进展判断、F16 预审风险标签、事件 fast path 复核 |
| 执行/生成 | 长输出、质量敏感 | **M**（qwen3.5） | 任务执行、周报/方案产出 |
| 审查/终判 | 质量最敏感、低频 | **L**（当前最强，可配云端） | eval judge、risk=high 任务的 precheck（强制 L） |

实现形态：gateway 增加 `SelectFor(purpose)`——purpose ∈ {judge, execute, review}，返回该档位模型；现有调用点按 purpose 改造。**风险联动**：预审产出的 `risk_level=high` 强制将执行档升到 L + 人工审批（F16 已有门）。

### 粒度 3：任务级动态路由——F18-b
```
任务进入 → 轻量打分器（纯规则，不调模型）：
  静态信号：priority、prompt 长度、是否含 handoff/审批指令、任务类型标签
  动态信号：该 agent 近期成功率（store 可查）、预算余量（F5 usage 数据）
  预审信号：risk_level（F16 产出）
→ 档位 S / M / L
→ 升级通道：执行中连续失败 2 次 或 看门狗判停滞 → 自动升一档重试（escalation）
→ 降级通道：预算余量 <20% → 强制降一档（预算感知，与 F5 熔断衔接：熔断是断路器，降档是节流阀）
→ 每次升降级落 run_steps（name=model-S/L, note=触发原因），路由决策可观测
```

## 三、策略评估：四个指标（工具全部现成）

| 指标 | 判定 | 工具 |
|---|---|---|
| **质量不降** | 同一 eval 数据集跑「全 M」vs「路由策略」，score_avg 差距 <1 分为合格 | eval 引擎直接 A/B |
| **成本/延迟** | 决策类调用 p99 从秒级降到百毫秒级；token 总量下降可量化 | usage 看板 by_model |
| **路由一致率** | 抽样小模型判断给强模型复判，agreement >85% 路由才可信 | eval 数据集改造（复判集） |
| **升级率健康区间** | <5% 大模型空转；>30% 小模型挡不住事；健康 5%-15% | run_steps 升级记录聚合 |

四指标产出「路由评测报告」——评测驱动路由调优，与 F17 处方闭环衔接（路由参数也是处方可调项）。

## 四、明确不做（取舍与反面）

- **不做学习型 router（RouteLLM/分类器打分）**：样本量不够（个人平台日任务量级 ~百），规则打分器可解释、可调试、零训练成本；等有真实流量日志再说，触发条件写死：连续两周 >1000 任务/周
- **不做 token 级实时路由**（prompt 中途换模型）：复杂度高收益存疑，步骤级分流已覆盖主要收益
- **不做跨云商比价**：v1 只有本地 Ollama 档位；接 API 后按定价表扩展，gateway 的注册表结构已预留

## 五、实现拆片（进 ROADMAP F18）

- **F18-a**：gateway `SelectFor(purpose)` + 三个调用点改造（看门狗/预审/handoff 决策走 S）+ by_purpose 用量维度
- **F18-b**：任务级打分器（纯规则）+ 升降级通道 + trace 留痕 + risk_level 联动
- **F18-c**：路由 A/B 评测报告（四指标）+ 用量看板升级
